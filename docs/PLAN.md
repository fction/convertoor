# Convertoor — исследование и план разработки

Convertoor рассчитан на личный сценарий. Пользователь входит в студию, открывает файл с устройства и получает короткий список подходящих действий. За единицу проектирования взята операция над медиадорожкой. Например, у MP4 со звуком есть извлечение MP3, у немого MP4 есть только экспорт и сжатие видео, а M4A с обложкой открывается как аудио.

## Проверка опубликованной версии

24 ноября 2026 года для проверки использовались синтетические PNG, WAV и MP4 со звуком. В Edge на production-сайте выполнены семь операций со скачиванием и независимым чтением результата через FFprobe. Примеры ниже иллюстрируют поведение на этих конкретных файлах.

| Операция | Исходник | Результат |
|---|---:|---:|
| PNG → WebP | 200 Б | 86 Б |
| WAV → Ogg Vorbis | 88 278 Б | 6 538 Б |
| Извлечение MP3 из MP4 | 20 121 Б | 21 645 Б |
| MP4 → MP4 с профилем сжатия | 20 121 Б | 17 503 Б |

Дополнительно проверены PNG → JPEG, WAV → FLAC и MP4 → WebM. За время обработки тестовых файлов браузер не отправил ни одного запроса с их содержимым. Прямой запрос закрытого JavaScript без сессии вернул HTTP 401. После выхода запрос к API сеанса также вернул 401.

## Путь файла в первой версии

1. Vercel проверяет логин и пароль и выдаёт часовую cookie. Рабочая страница и её модули требуют действующего сеанса. GitHub Pages переводит на HTTPS-страницу входа.
2. Браузер принимает один непустой файл за раз. Первые байты определяют семейство контейнера. Затем воркер через WORKERFS читает нужные участки оригинала. Расширение и заявленный браузером MIME не участвуют в решении.
3. В отдельном Web Worker запускается локальная для вкладки копия FFmpeg/WASM. FFprobe уточняет типы дорожек, их индексы, размеры и длительность. Встроенная обложка не превращает аудио в видео. Неподдерживаемый контейнер или файл без читаемых дорожек получает сообщение об ошибке.
4. Интерфейс строит список операций из обнаруженных дорожек. Пользователь выбирает действие, формат и профиль. Для PNG, WAV и FLAC профиль отключён. При повторном выборе файла предыдущая задача уничтожается.
5. Воркер получает предопределённый набор аргументов и внутреннее имя файла. Никакие имена пользователя не подставляются в команду. При экспорте исключаются глобальные метаданные, главы и дополнительные дорожки. Загрузка результата идёт из локального Blob.
6. На экране видны исходный и итоговый размер, включая случай, когда новый файл получился больше. Кнопки отмены и очистки освобождают воркер и URL результата. Пользовательские файлы, имена и история операций на сервере студии не сохраняются.

| 2. Определение класса — реализовано | Объединить сигнатуру и проверку дорожек. Выбирать первую основную видео- и аудиодорожку. | 3. ## Границы первой версии

Стоимость обработки по памяти и CPU несёт устройство пользователя. Ограничения составляют 40 Мп, 8192 пикселя по стороне и 30 минут для известной длительности. Итоговый файл хранится в памяти вкладки до скачивания или очистки. Экспорт останавливается после пяти минут без продвижения. Сжатие не гарантирует конкретного размера. На маленьком файле контейнер и заголовки иногда занимают больше места, чем удаётся сэкономить.

В production используются HTTPS, защищённая cookie, ограничение источников скриптов и запросов и самохостинг медиадвижка. В проекте Vercel активно правило Firewall для POST-запросов с параметром view=login. Порог — 12 запросов за 10 минут с одного IP. В самом приложении дополнительно действует лимит в шесть попыток на экземпляр за 10 минут. Выход удаляет cookie в текущем браузере. Ранее скопированный билет действует до истечения часа или смены секрета с повторным развертыванием. Корректность устройства, расширений браузера, аккаунтов GitHub и Vercel остаётся частью модели доверия.

GitHub Pages раздаёт статические ресурсы. Серверная проверка доступа выполняется в Vercel Function. Вычисления FFmpeg выполняются в воркере браузера.
